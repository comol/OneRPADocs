# MCP в Pi и DSH

MCP-серверы дают агенту справку платформы, поиск по коду и метаданным, граф связей, БСП, шаблоны, проверку синтаксиса и проверку через 1С:Напарник. Как поднять Docker-образы, ключи и каналы — в разделе [MCP серверы для 1С](../mcp-servery-1c/README.md). Бандл образы не содержит и контейнеры не стартует.

Пока нужные серверы не запущены, чат открывается. В Pi это режим **degraded**: нет инструментов конкретного молчащего сервера, правки файлов и скрипты навыков остаются. В DSH отсутствие необязательного сервера — предупреждение, а смысловая правка метаданных ждёт живой обязательный MCP и свежий индекс. Задачу нельзя считать проверенной через 1С, пока эти условия не выполнены.

## Серверы поставки

| Назначение | Pi, id | DSH, id | Порт |
|---|---|---|---|
| Код и метаданные | `1c-code-metadata-mcp` | `onec_code` | 8000 |
| Синтаксис BSL | `1c-syntaxcheck-mcp` | `onec_syntax` | 8002 |
| Справка платформы | `1c-docs-mcp` | `onec_docs` | 8003 |
| Шаблоны | `1c-templates-mcp` | `onec_tpl` | 8004 |
| Граф метаданных | `1c-graph-metadata-mcp` | `onec_graph` | 8006 |
| 1С:Напарник | `1c-code-checker-mcp` | `onec_checker` | 8007 |
| БСП | `1c-ssl-mcp` | `onec_ssl` | 8008 |
| UI-тесты | `1c-qa` | `onec_qa` | 8030 |

В DSH отдельный Code необязателен, если подключённый Graph уже отдаёт поиск кода. Это не добавляет Graph проверку XML по XSD и другие методы Code: смотрите каталог методов на карточке сервера.

## Кто обязателен

В **Pi** режим ready — это семь серверов таблицы, кроме QA. Недоступность `1c-qa` сессию в degraded не переводит. В манифесте есть ещё `1c-data-mcp`: HTTP-сервис опубликованной базы, адрес из `INFOBASE_PUBLISH_URL` и `/hs/mcp`. По умолчанию он выключен и в готовность не входит.

В **DSH** обязателен Graph. Code обязателен, пока у подключённого Graph не подтверждён метод `search_code`. Справка, шаблоны, БСП, синтаксис, Напарник и QA обязательными не считаются: их отсутствие видно на карточке и чат не останавливает.

Отдельный сервер данных `onec_data` поднимается, когда задан адрес публикации базы. Своего фиксированного порта у него нет.

И в Pi, и в DSH адрес без успешной проверки соединением не считается подключением.

Имена методов в Pi имеют вид `mcp_<server>_<tool>`. В обычном режиме модель не получает все схемы сразу: она ищет метод через `tool_search` и вызывает его через `tool_dispatch`. Живая проверка сверяет identity, каталог и схему. Расхождение не рвёт сессию: остаётся пересечение с разрешённым списком. Административные методы — перезагрузка плагинов сервера, удаление проектов графа, произвольный Cypher, запись памяти шаблонов — модели не отдаются.

## Как проверить

**Pi:** `/mcp1c`, `/mcp1c reconnect`, `/checkmcp`, `/index1c status`, `/preflight1c`. Установщик и `--doctor` делают live-probe. `reconnect` без аргумента переподключает включённые, но молчащие серверы; `all` или id сервера переподключает принудительно, без перезапуска Pi. Расхождение каталога здесь предупреждение. Строго его отвергает probe установщика и `--doctor`.

**DSH:** «Настройки → MCP: серверы», на карточке «Предпросмотр» → «Проверить» → «Сохранить». Вкладка «MCP 1С» справа открывает те же настройки. Из консоли — `DSH-Desktop-1C.exe --doctor`. Недоступный MCP даёт предупреждение; код 1 — поломка профиля поставки, а не тихий сервер. После сохранения нового URL адреса уже можно проверить, но ход агента увидит их после полного перезапуска, включая выход из трея.

Сервер, поднятый после старта сессии Pi, сам в ней не появится: нужен `/mcp1c reconnect`. В DSH новый процесс сервера подхватывается перезапуском. В control center при росте каталога есть «Перезапустить хост».

Сторонний HTTP или stdio сервер подключается к проекту отдельно: в Pi — `/mcp-project`, в DSH — «Дополнительные серверы» и файл `.mcp.json`. Если адрес совпадает с уже включённым сервером бандла, работает сервер бандла, а дубль пропускается.

## Индексация

Поиск по вашей конфигурации требует выгрузки и индекса Code и Graph. Свежесть выгрузки смотрите в Pi командой `/freshness1c`, переиндексацию после выгрузки — `/sync1c` и `/index1c`. В DSH состояние индекса видно на карточке сервера, действия обновления и отмены — в «Подробностях индексации».

`/index1c start`, `reindex`, `cancel` и `retry` в Pi вызываются только если сервер объявил такой метод. Иначе команда честно отвечает `unsupported`.

После успешной загрузки исходников в базу DSH запускает переиндексацию code MCP и привязанного проекта graph. Пока индекс не подтверждён, старый поиск закрыт и остаются локальные файлы. Если MCP недоступен или не задан `graphProjectId`, причина показывается, а сама загрузка базы из-за этого не отменяется.
