# Проверка и сдача в Pi

Синтаксис, загрузка в базу и приёмка — разные шаги. Локальный BSL Language Server не заменяет тест в 1С.

## Локально, без MCP

Java и BSL Language Server 1.0.7 уже в поставке.

```text
/bsl status
/bsl restart
/bsl preview <текст или путь>
```

В чате можно попросить: «Проверь локальным BSL LS модуль <путь>».

`/deslop` сначала показывает, какие следы генерации он убрал бы из BSL, и применяет список только по запросу. Поведение модуля он менять не должен.

`/preview1c` открывает `Form.xml` или `Template.xml` в браузере только для чтения. `/graph1c` рисует связи объекта через графовый MCP. `/borrow1c` заимствует объект в расширение на файлах и к базе ничего не применяет.

`/verify-changes ["A.bsl","B.xml"]` фиксирует полный набор файлов после команд и проверяет его. Пустой список означает, что исходники не менялись.

## В тестовой базе

| Команда | Что делает |
|---|---|
| `/deploy-and-test` | Загружает конфигурацию в тестовую базу из `.dev.env` и прогоняет UI-тесты веб-клиента |
| `/test-fix-loop` | Повторяет развёртывание и тест, пока сценарии не пройдут или не кончится бюджет итераций |
| `/journal1c` | Последние события журнала регистрации, не технического журнала |
| `/formshot` | Снимок формы штатными средствами: браузер, EDT или windows-mcp. Свой OCR бандл не пишет |
| `/uitests on\|manual\|off` | Когда вообще запускать UI-тесты |
| `/restore-testbase` | Приводит тестовую базу к снимку `.dt` и текущим исходникам |

`/manual-check Работает|Ошибка|Изменить` записывает результат ручной проверки после неудачной автоматической. `/features` задаёт ворота проверок, строгость ревью, модель ревью, версию платформы и базу БСП для справки. `/receipt` собирает отчёт о файлах и командах сессии, `/receipt html` экспортирует его.

`/help-version` отвечает по справке версии платформы и БСП и умеет сравнить две версии. Фильтр БСП реально ограничивает базу `ssl_search`. У справки платформы отдельного полного корпуса на каждую версию нет: используются общий корпус и поля доступности, если они есть.

## Сдача

| Команда | Что делает |
|---|---|
| `/build-release` | Собирает `.cf` и `.cfe` из зафиксированных исходников. «Собрать» — бинарник в `build/`, не копия XML |
| `/merge1c` | План нетипового обновления. Первый вызов — план, `apply` — только команды CFE. По умолчанию dry-run |
| `/tasks set <change> <id> done <rev> <доказательство>` | Закрывает задачу OpenSpec |
| `/opsx-archive` | Архивирует change после preview и проверки revision |
| `/check-uuid` | Ищет дубли UUID в XML-выгрузке |

`/meta-apply` — дополнительный план правки метаданных с проверкой revision. Он не заменяет навык `1c-metadata-manage`. `/previewmode` показывает diff метаданных до записи: `on`, `auto` или `off`.

## Объяснить, что изменилось

`/explain-changes` разбирает правки текущей ветки по процедурам и смыслу. `/next-step` предлагает следующий шаг и подставляет запрос, который можно отредактировать. `/debug1c` ведёт отладку через гипотезы и помеченные записи журнала. `/map1c` строит карту механизма и умеет сохранить её по имени.
