# Автономия Pi

Автономная работа не обходит ASK/PLAN/BUILD и обычные подтверждения. Ни пульс, ни отложенное сообщение, ни восстановление цели не вызывают модель, пока нет вашего действия или уже запущенного цикла.

## Цель

`/goal <цель>` ведёт цикл до проверяемого результата и не задаёт уточняющих вопросов. Лимиты по умолчанию: 300 вызовов инструментов, 40 итераций, 120 минут. Их меняют в `/economy-settings`, вкладка «Автономность». Цель доступна только в BUILD.

`/goal-resume` продолжает незавершённую цель. Состояние лежит в каталоге состояния, не в проекте. `/goal-cancel` останавливает активную цель.

`/auto` показывает маршрут ролей research, planning, development, testing и review. Если роль не настроена, берётся проверенная модель текущей сессии. `/roles` редактирует эти назначения. `/service-models` отдельно задаёт модель классификации задачи и модель поиска: `auto` или `provider/id`.

## Расписание и фон

| Команда | Что делает |
|---|---|
| `/later 30s <текст>` | Откладывает сообщение. Также `5m`, `2h` или миллисекунды. Переживает перезапуск |
| `/check every 30m <текст>` | Регулярная проверка. Ещё `5m`, `list`, `cancel <id>` |
| `/loop 5m <текст>` | Цикл с критерием завершения. Без интервала открывается меню |
| `/heartbeat` | Пульс длинной сессии без фоновых ходов модели |
| `/continue` | Одно сообщение «продолжи» с подтверждённого состояния |
| `/sessions` | Сводка фона: пульс, later, проверки, ACP |
| `/bg <команда>` | Команда в фоне. Ограничения путей информационной базы сохраняются |
| `/jobs`, `/logs <id>`, `/kill <id>` | Список, вывод и остановка фона |
| `/operations` | Долгая операция: в фон, продлить, отменить, забрать результат |

`/question-timeout on` разрешает автовыбор обычного вопроса через 5 минут. `/awake on` не даёт Windows уснуть на время работы агента. Экран при этом может погаснуть.

## Субагенты

`/run <агент> <задача>` запускает одного субагента. Каждый ребёнок заканчивает ответ секцией `## Upstream Handoff`. В параллельной пачке не больше одного пишущего.

`/subagents` открывает метаданные, модели и промпты. Рядом есть стоимость (`/subagent-cost`), остановка (`/subagents-stop`), подсказка живому ребёнку (`/subagents-steer`) и диагностика (`/subagents-doctor`). Handoff проверяется у результата на переднем плане. Фоновый запуск и результат только в файл этой проверкой не покрыты.

`/handoff <цель>` переносит контекст в новую сессию и оставляет текущую родителем. `/background` — то же имя действия.

## ACP

`/acp-connect` открывает исходящую сессию к другому агенту. `/acp-disconnect` её закрывает. `/acp1c` показывает сессии бандла. В DSH одноимённый `/acp-connect` означает другое: там DSH сам принимает внешний клиент.

## Очередь и побочные вопросы

`/queue` и `/q` ставят сообщения по одному. `/steer` подсказывает текущему ходу. `/btw` задаёт короткий вопрос мимо основного разговора. `/plan` — отдельный режим плана с вопросами и сдачей плана. Это не то же самое, что `/access plan`, который только ограничивает запись.

## Проектные инструкции

Лаунчер по умолчанию не подмешивает внешние `AGENTS.md` и `CLAUDE.md`. `/project-agents` показывает превью и включает проектный `AGENTS.md` явно, с потолком 16 КиБ. Импорт выбранного контекста Codex, Claude и Cursor с предпросмотром — `/import-agent`.
