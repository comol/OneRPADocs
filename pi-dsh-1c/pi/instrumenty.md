# Инструменты и навыки Pi

Штатные инструменты Pi внутри проекта: `read`, `grep`, `find`, `edit`, `write`. Путь обязан остаться в рабочей папке. Не читаются `.dev.env`, `auth.json`, `*.1CD`, `.git`, `.pi`. Не пишутся XML и EDT, каталоги инструкций проекта, исполняемые форматы Windows, PowerShell, WSH, Office-макросы и Unix, а также `.dev.env` и `.v8-project.json`. Выход по `..`, абсолютный путь наружу, `~`, `file://` и symlink отвергаются.

`ls`, `bash` и `powershell` модели выключены. `grep` и `find` работают закреплёнными `rg.exe` 14.1.1 и `fd.exe` 10.3.0 из поставки, а не свежими бинарниками из сети.

Поиск процедуры начинается с MCP. `grep` и `find` допустимы, когда в каталоге подключённых MCP нет подходящего метода, сервер недоступен, две существенно разные попытки ничего не дали или индекс заведомо старше свежих локальных правок. Перед переходом агент называет, что уже пробовал.

## Чем агент пользуется сверх файлов

| Инструмент | Зачем |
|---|---|
| `tool_search`, `tool_dispatch` | Найти метод MCP и вызвать его, не загружая все схемы |
| `mcp_1c_status` | Кратко или подробно: identity, каталог, схемы |
| `onec_resource` | Правила, навыки и секции маршрута. К исходникам проекта доступа нет |
| `onec_openspec` | Список, выбор, проверка и запись артефактов OpenSpec |
| `onec_skill_script` | Один из 71 хешированного скрипта навыков, через отдельный host с лимитом вывода |
| `onec_bsl_query` | Диагностика, hover, definition и references локального BSL Language Server 1.0.7 |
| `knowledge_1c` | Факты и правила из `.ai-rules/knowledge` по теме |
| `memory` | recall и remember. Порядок backend: OpenViking, Cognee, память шаблонов, файл. Секреты не пишутся |
| `local_extension` | Локальный plugin или skill: записать, проверить, включить, откатить |
| `subagent` | Делегирование. Ответ ребёнка заканчивается секцией `## Upstream Handoff` |
| `ask_user_question` | Вопрос вам. Внутри `/goal` подавлен |

Произвольный `.ps1`, команда, собранная моделью, и скрипт проекта не исполняются. Аргументы скрипта — только `-Имя:значение` или отдельный switch. Позиционные аргументы, выбор интерпретатора, прямые учётные данные и пути вне проекта блокируются.

В degraded остаются чтение, поиск и правка файлов внутри проекта, скрипты навыков и методы тех MCP, которые реально ответили. Методы молчащих серверов недоступны.

## Навыки

Список — `/skills`. Вызов — `/skill:<имя>`. Основные навыки поставки:

- `pi-bundle-help` — ответы о настройке самого бандла
- `mcp-1c-tools` — каталог методов MCP с параметрами
- `1c-metadata-manage` — объекты, формы, СКД, макеты, роли, EPF/ERF, CFE, CF, базы, подсистемы
- `1c-repository-manage` — хранилище: захват до правки, помещение после проверки
- `1c-event-journal`, `1c-form-shot`, `1c-ai-merge`, `1c-verify-project`
- `v8unpack-cf` — бинарные формы и CF/CFE/EPF без платформы
- `document-import` — PDF, DOCX и XLSX в Markdown
- `pi-extensions`, `skill-maintainer` — свои плагины и навыки
- шесть навыков OpenSpec: propose, explore, apply, update, archive, sync

Правила 1С и 13 ролей лежат в поставке и подгружаются по задаче, а не целиком в каждый ход.

Промпты `agent/prompts/` вызываются как `/имя` и являются инструкцией агенту. Это не кнопки, которые сами обновляют базу. Их список — в [командах](komandy.md), строки с видом «промпт».

## Что установлено, но не включено

Часть npm-пакетов лежит в поставке и не смонтирована: второй владелец той же функции, несовместимый host или возврат закрытых встроенных инструментов. `/installtools` показывает блок «Опции (есть в сборке, выключены)». Не считайте их рабочими возможностями, пока строка расширения явно не включена в поставке.

Память Cognee и OpenViking, EDT-MCP, Agent Browser, Windows-MCP, Headroom и RTK бандл не поднимает. `/installtools` показывает, установлены они или только описаны. Включение RTK — ключ `RTK` в `.dev.env` или `/economy-settings`. Второй компрессор рядом с уже включённым не добавляют.
