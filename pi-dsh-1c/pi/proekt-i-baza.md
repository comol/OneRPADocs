# Проект, база и состояние Pi

## Где что хранится

| Данные | Где |
|---|---|
| Логин, список проектов, история, общие настройки, автономность, локальные расширения | Каталог состояния вне поставки: `Pi1C\state` в профиле пользователя. Точный путь печатает `Pi-1C.exe --settings`. Переопределение — `PI1C_STATE_DIR` |
| Модель новых сессий выбранного проекта | `<проект>/.pi/settings.json` |
| Платформа, база, префикс, режимы | `<проект>/.dev.env` |
| Знания конфигурации | `<проект>/.ai-rules/knowledge/` |
| Change OpenSpec | `<проект>/openspec/` |

Каталог состояния не может лежать внутри поставки: лаунчер откажется стартовать. Обычный запуск в папку дистрибутива не пишет. Переустановка сохраняет логин, историю и настройки. Удаление папки сборки историю не уничтожает.

Корень бандла, рабочий стол и корень репозитория проектом не считаются.

Новая сессия сохраняется сама. «Сессия без сохранения» и `--no-session` — временная работа. `--continue` продолжает последнюю, `--resume` открывает историю.

## База

«Настройки базы 1С…» → вкладка «База 1С» → «Из списка 1С» подставляет имя, тип и адрес из штатных списков 1С. Пароль, пользователь и версия совместимости при этом не меняются. Ручной ввод остаётся. В `.dev.env` запись попадает только по «Сохранить и запустить».

`/project1c` показывает параметры проекта без секретов. `/status1c` — вид задачи, качество, доступ, MCP, базу, OpenSpec, память и экономию. `/preflight1c` повторяет проверку модели, проекта, MCP, платформы, backend и свежести выгрузки.

Пять полей мастера `/setup`: `PLATFORM_PATH`, `PLATFORM_VERSION`, `USE_EDT`, вид и путь информационной базы, `PREFIX`.

## Как Pi говорит с 1С

`ONEC_BACKEND` выбирает способ связи. По умолчанию это MCP бандла, вручную для обычной работы backend не переключают.

`/backend1c` объясняет текущий способ. Особые значения — `com`, `external-mcp`, `epf`. `/backend1c probe` живо проверяет COM и данные не меняет. Семь из семи MCP подтверждают серверы, а не доступ к конкретной базе: базу проверяют отдельно.

## Выгрузка и загрузка

| Направление | Команда |
|---|---|
| Вся конфигурация или расширение из базы в файлы | `/loadfrom1cbase` |
| Отдельные объекты из базы в файлы | `/getconfigfiles` |
| Свежесть, выгрузка и переиндексация | `/sync1c` |
| Файлы в базу и обновление структуры | `/update1cbase` |
| Центр деплоя: план, запуск, статус, отмена | `/1c-deploy` |
| Снимок `.dt` плюс текущие исходники в тестовую базу | `/restore-testbase` |
| Цель: основная конфигурация или расширение | `/target1c status\|base\|extension:Имя` |

Контейнер нового объекта выбирается по правилу проекта, а не молча. Загрузка в базу требует BUILD и обычного подтверждения.

## Документы и соседние каталоги

`/docs add <папка>` подключает документы проекта, `show`, `search` и `read` работают по ним. `/document-import <путь>` в BUILD забирает PDF с текстом, DOCX или XLSX из проекта и кладёт Markdown в `.pi/document-imports/`. Это локально, без OCR и без облака.

`/add-dir <путь>` подключает внешнюю папку только для чтения. `list` и `clear` управляют списком.

## Переход со старых версий

В версиях 1.0.5 и старше логин и сессии лежали внутри сборки: `agent\auth.json` и `agent\sessions`. Перенесите их один раз в каталог состояния, который показывает `--settings`. Не удаляйте старую папку, пока не проверите вход и историю. Скрипт копирования должен останавливаться на первой ошибке, а не молча пропускать файлы.

## Голос

`/install-openwhispr` ставит внешнее приложение OpenWhispr через winget. `/openwhispr` открывает его, Ctrl+Alt+W — то же. Распознавание настраивается в самом OpenWhispr; для него рекомендуется OpenAI API. Текст диктовки остаётся черновиком, пока вы его не отправите.
