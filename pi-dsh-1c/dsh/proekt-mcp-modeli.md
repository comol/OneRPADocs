# Проект, MCP и модели DSH

## Модель

Одно окно **«Модели и подписки»**: сверху подписки Cursor, xAI/Grok, Claude Max, OpenAI/Codex и GitHub Copilot, ниже доступные модели и поиск. Назначения ролям свёрнуты. Неподключённая модель помечена и не выбирается. Наличие CLI входом не считается.

Claude — только подписка Max через официальный Claude Code. Cursor — действующая подписка. Платный Anthropic API не используется. Отказ провайдера показывается текстом.

Ключ DeepSeek можно задать переменной окружения `DEEPSEEK_API_KEY`. Модель, провайдер и ключ хранятся в хранилище DSH, не в `.dev.env`.

`/models1c` и `dsh-1c.ps1 -Models` печатают провайдеры и модели без секретов. `-Models delegates` показывает делегатов.

Поля «Модель определения типа задачи» и «Модель поиска» по умолчанию пустые: берётся самая дешёвая совместимая модель из уже настроенных. Явный `provider/id` задаёт предпочтение. Если цена неизвестна, экономия не обещается. При ошибке дешёвой модели работает обычный fallback, затем основная модель. Классификация не меняет выбранный вид задачи и ASK/PLAN/BUILD.

## `.dev.env`

Файл лежит в папке проекта. Его создаёт форма первого запуска или `dsh-1c.ps1 -Init`. Шаблон — в поставке. Форма добавляет `.dev.env` в `.gitignore` и может подставить платформу и режим совместимости из `Configuration.xml`.

Дальше параметры этой папки — **«Настройки → Настройки проекта 1С»**. При смене проекта черновик и введённые пароли сбрасываются. Пустое поле пароля сохраняет прежнее значение. Конфликт ревизии требует «Обновить».

**«Настройки → 1С: среда»** показывает остальные подключения текущего запуска. Их источник — `.dev.env` стартового проекта, путь виден в форме. Сохранение базы другого проекта не перенастраивает уже запущенные службы: для другой базы запустите DSH с её папкой.

Пароли и ключи в чат не попадают. Форма показывает только признак «задан».

Основные группы ключей:

| Группа | Ключи |
|---|---|
| Платформа | `PLATFORM_VERSION`, `PLATFORM_PATH`, `USE_EDT` |
| База | `INFOBASE_NAME`, `INFOBASE_ENVIRONMENT` (`test`, `dev`, `production`, `unknown`), `INFOBASE_KIND`, `INFOBASE_PATH`, `IB_USER`, `IB_PASSWORD`, `INFOBASE_PUBLISH_URL` |
| Проект | `EXTENSION_NAME`, `PREFIX`, `NEW_OBJECTS_IN`, `EXPORT_PATH`, `EXTENSIONS_PATH`, `UI_TESTING`, `SUPPORT_GUARD` |
| Хранилище | `REPOSITORY_PATH`, `REPOSITORY_USER`, `REPOSITORY_PASSWORD` |
| Поддержка | `SUPPORT_KEY`, `SUPPORT_EMAIL` |
| Режимы | `VERIFICATION_DEPTH`, `ORCHESTRATION`, `ONEC_MODE_DEFAULT`, `YOLO_MODE`, `ONEC_EXECUTION_BACKEND` |
| MCP | `ONEC_MCP_<ИМЯ>_URL`, `ONEC_MCP_<ИМЯ>=off` |

`INFOBASE_ENVIRONMENT` — справочная метка, не запрет операций. `SUPPORT_GUARD=deny` защищает типовые объекты на поддержке и переносит изменение в расширение. Для этого в выгрузке нужен понятный `Ext/ParentConfigurations.bin`. Отсутствие файла не доказывает, что поддержки нет, и не доказывает, что она есть.

`ONEC_EXECUTION_BACKEND`: `bundled-mcp`, `com`, `external-mcp` или `epf`. Пустое значение не выбирает backend само.

## MCP

Карточки: **«Настройки → MCP: серверы»**. Порядок на карточке — «Предпросмотр», «Проверить», «Сохранить». «Методы и описания» показывает имена и не вызывает инструменты.

Семь серверов и порты — на странице [MCP в Pi и DSH](../mcp.md). Смена URL применяется после полного перезапуска, включая трей.

Сторонний сервер проекта пишется в `.mcp.json`. Если его адрес совпадает с сервером бандла, подключается сервер бандла, а дубль пропускается одной строкой в контексте.

Сервер данных и прочие дополнительные URL включаются отдельно (`ONEC_MCP_DATA` и соседние ключи). Установка пакета, флажок и живое соединение — три разных состояния. `/installtools status` показывает их раздельно.

## Новый проект

«Добавить рабочую область» открывает мастер: сначала CF или DT, затем отдельная база, исходники и MCP. В конце проект можно сохранить на потом или отдать подготовку агенту. Повторно тот же мастер — `/project-setup` (алиас `/setup`), затем `/project-init`.

`/config scaffold` создаёт каркас `src/{cf,cfe,epf,erf}`, `build/`, `.ai-rules/knowledge/` и `.gitignore`. Сам `.dev.env` он не пишет: печатает рекомендуемые значения.

Импорт контекста из Cursor, Claude Code или Codex — `/dsh-1c` с предпросмотром. Предложение переноса для папки, где контекст уже найден, показывается один раз. Ручной перенос остаётся.

## Память

**«Настройки → Инструменты 1С → Память: Cognee и OpenViking»**. Для Cognee нужен HTTP API сервера, обычно порт 8010, без суффикса `/mcp`. После сохранения настроек перезапустите DSH. Сервер памяти бандл не поднимает.

Уроки сессий лежат в состоянии бандла и подмешиваются к похожей задаче. Каталог автономии проекта — в данных приложений пользователя, не в исходниках. В проект бандл сам пишет `.dev.env`, `openspec/`, `.ai-rules/knowledge/`, одобренный `LLM-RULES.md` и результат импорта, который вы запросили.
