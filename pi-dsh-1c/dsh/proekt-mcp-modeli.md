# Проект, MCP и модели DSH

## Модель

Окно **«Провайдеры и модели»**: группы «Аккаунты и подписки» и «Другие API», поиск и список «Показывать». Назначения ролям открываются кнопкой «Модели для ролей 1С». Неподключённая модель помечена и не выбирается. Наличие CLI входом не считается.

Подписки: Claude Max, Cursor, OpenAI/Codex, GitHub Copilot, Grok, Kimi Code, Coding Plan GLM и Qwen, Google Gemini и Meta Muse через официальные CLI, OpenCode Go. Несколько аккаунтов одного провайдера — в той же группе. Порядок основной и резервных моделей — кнопка **«Ротация моделей»**, внутри раздел **«Основная и резервные модели»**. Подробно — [Модели, подписки и аккаунты](../modeli-i-podpiski.md).

Claude — только подписка Max через официальный Claude Code. Cursor — действующая подписка. Платный Anthropic API не используется. Отказ провайдера показывается текстом.

Ключ DeepSeek можно задать переменной окружения `DEEPSEEK_API_KEY`. Модель, провайдер и ключ хранятся в хранилище DSH, не в `.dev.env`.

`/models1c` и `dsh-1c.ps1 -Models` печатают провайдеры и модели без секретов. `-Models delegates` показывает делегатов.

Поля «Модель определения типа задачи» и «Модель поиска» по умолчанию пустые: берётся самая дешёвая совместимая модель из уже настроенных. Явный `provider/id` задаёт предпочтение. Если цена неизвестна, экономия не обещается. При ошибке дешёвой модели работает обычный fallback, затем основная модель. Классификация не меняет выбранный вид задачи и ASK/PLAN/BUILD.

## `.dev.env`

Файл лежит в папке проекта. Его создаёт форма первого запуска или `dsh-1c.ps1 -Init`. Шаблон — в поставке. Форма добавляет `.dev.env` в `.gitignore` и может подставить платформу и режим совместимости из `Configuration.xml`.

Дальше параметры этой папки — **«Настройки → Настройки проекта 1С»**. При смене проекта черновик и введённые пароли сбрасываются. Пустое поле пароля сохраняет прежнее значение. Конфликт ревизии требует «Обновить».

Поле **«Найти параметр»** (подсказка «База, платформа, префикс…») оставляет на экране только подходящие поля.

**«Проверить подключение»** проверяет введённые значения до сохранения. Пока проверка идёт, кнопка называется «Проверяю подключение…». Успех показывает «Подключение работает» и число секунд. Иначе форма пишет «Вход в базу не подтверждён» и список шагов. Результат относится к тем значениям, с которыми его получили: после правки черновика проверьте снова. Пароль в ответ не попадает. Сначала проверяются каталог или сервер базы и платформа. В Windows следом выполняется вход внешним соединением. Если соединения 8.3 нет или его библиотека удалена, используется 8.5. Пока 8.3 на месте, выбирается оно. Конфигуратор не запускается, база не блокируется. Если платформа не указана, форма предупреждает, что выгрузка и загрузка через Конфигуратор без неё не запустятся. На Linux и macOS вход внешним соединением остаётся непроверенным, остальные шаги выполняются. Пароль в текст результата не входит.

При открытии проекта его настройки переносятся в папку проекта, в каталог `.dsh-1c`. Переносятся пресет, назначения навыков и проектные MCP, и только если своего файла в проекте ещё нет. Файл, который уже лежит в проекте, не заменяется. Прежняя копия в данных DSH остаётся. Общие настройки DSH и история чатов остаются при установке. Если в `.gitignore` нет строки `.dsh-1c/`, она добавляется.

**«Настройки → 1С: среда»** показывает остальные подключения текущего запуска. Их источник — `.dev.env` стартового проекта, путь виден в форме. Сохранение базы другого проекта не перенастраивает уже запущенные службы: для другой базы запустите DSH с её папкой.

Пароли и ключи в чат не попадают. Форма показывает только признак «задан».

Основные группы ключей:

| Группа | Ключи |
|---|---|
| Платформа | `PLATFORM_VERSION`, `PLATFORM_PATH`, `USE_EDT` |
| База | `INFOBASE_NAME`, `INFOBASE_ENVIRONMENT` (`test`, `dev`, `production`, `unknown`), `INFOBASE_KIND`, `INFOBASE_PATH`, `IB_USER`, `IB_PASSWORD`, `INFOBASE_PUBLISH_URL` |
| Проект | `EXTENSION_NAME`, `PREFIX`, `NEW_OBJECTS_IN`, `EXPORT_PATH`, `EXTENSIONS_PATH`, `UI_TESTING`, `SUPPORT_GUARD` |
| Хранилище | `REPOSITORY_PATH`, `REPOSITORY_USER`, `REPOSITORY_PASSWORD` |
| Режимы | `VERIFICATION_DEPTH`, `ORCHESTRATION`, `ONEC_MODE_DEFAULT`, `YOLO_MODE`, `ONEC_EXECUTION_BACKEND` |
| MCP | `ONEC_MCP_<ИМЯ>_URL`, `ONEC_MCP_<ИМЯ>=off` |

`INFOBASE_ENVIRONMENT` — справочная метка, не запрет операций. `SUPPORT_GUARD=deny` защищает типовые объекты на поддержке и переносит изменение в расширение. Для этого в выгрузке нужен понятный `Ext/ParentConfigurations.bin`. Отсутствие файла не доказывает, что поддержки нет, и не доказывает, что она есть.

`ONEC_EXECUTION_BACKEND`: `bundled-mcp`, `com`, `external-mcp` или `epf`. Пустое значение не выбирает backend само.

## MCP

Раздел **«Серверы MCP»**. Проектные MCP связаны с выбранной конфигурацией. Общие MCP используют одни настройки во всех проектах. Сервер раскрывается, чтобы изменить подключение.

**«Проектные MCP»**: настройки и токены относятся только к выбранному проекту.

**«Общие MCP»**: настройки и токены общие для всех проектов DSH.

Порядок на карточке — «Предпросмотр», «Проверить», «Сохранить». «Методы и описания» показывает имена и не вызывает инструменты.

Состав, порты и кто из серверов обязателен — на странице [MCP в Pi и DSH](../mcp.md). Новый URL можно проверить сразу после сохранения. Ход агента увидит его после полного перезапуска, включая выход из трея.

Сторонний сервер проекта пишется в `.mcp.json`. Если его адрес совпадает с включённым основным сервером, подключается основной сервер, а дубль второй раз не подключается.

Такая запись не показывается среди дополнительных. Карточка пишет: «Из .mcp.json не показаны записи, совпадающие с основными серверами», затем имя записи и основной сервер. Дальше: «DSH подключает каждый такой сервер один раз, как основной. Файл не меняется: эти записи по-прежнему видят Claude Code и другие агенты.»

Раздел **«Компьютер и браузер»**: агент управляет приложениями и браузером через общие MCP. Переключатели действуют во всех проектах и по умолчанию выключены.

- **«Управление компьютером»** — Agent Desktop 1.2.0. Агент видит окна программ, нажимает кнопки и пункты меню, вводит текст и делает снимки окна. Программа входит в поставку Windows и Linux Web. На macOS её ставит `/install-agent-desktop`.
- **«Управление браузером»** — Agent Browser, команда `/install-agent-browser`.

Обе команды передают процедуру в текущий чат. Чтобы агент мог пользоваться инструментом, включите его переключатель.

По умолчанию DSH читает правила сборки и `AGENTS.md` проекта. Файлы других агентов — `CLAUDE.md`, `.claude`, `.cursor` — подключаются отдельной настройкой «Правила других агентов».

Сервер данных и прочие дополнительные URL включаются отдельно (`ONEC_MCP_DATA` и соседние ключи). Установка пакета, флажок и живое соединение — три разных состояния. `/installtools status` показывает их раздельно.

## Новый проект

«Добавить рабочую область» открывает мастер: сначала CF или DT, затем отдельная база, исходники и MCP. В конце проект можно сохранить на потом или отдать подготовку агенту. Повторно тот же мастер — `/project-setup` (алиас `/setup`), затем `/project-init`.

`/config scaffold` создаёт каркас `src/{cf,cfe,epf,erf}`, `build/`, `.ai-rules/knowledge/` и `.gitignore`. Сам `.dev.env` он не пишет: печатает рекомендуемые значения.

Импорт контекста из Cursor, Claude Code или Codex — `/dsh-1c` с предпросмотром. Предложение переноса для папки, где контекст уже найден, показывается один раз. Ручной перенос остаётся.

## Память

**«Настройки → 1С: инструменты → Память: Cognee и OpenViking»**. Для Cognee нужен HTTP API сервера, обычно порт 8010, без суффикса `/mcp`. После сохранения настроек перезапустите DSH. Сервер памяти бандл не поднимает. Наборы данных Cognee, граф, загрузка папок в OpenViking — [Дополнительные возможности](dopolnitelnye-vozmozhnosti.md#память-cognee-и-openviking).

Уроки сессий лежат в состоянии бандла и подмешиваются к похожей задаче. Каталог автономии проекта — в данных приложений пользователя, не в исходниках. В проект бандл сам пишет `.dev.env`, `openspec/`, `.ai-rules/knowledge/`, одобренный `LLM-RULES.md` и результат импорта, который вы запросили.
