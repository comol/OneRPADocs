# Дополнительные возможности DSH

Всё ниже работает поверх обычного чата и не обходит ASK/PLAN/BUILD и подтверждения инструментов. После включения плагина или смены настроек, которые применяются при запуске, полностью перезапустите DSH, включая выход из трея. Ассистент описан отдельно: [Ассистент DSH](assistent.md).

## Команды агентов (beta)

Команда — несколько субагентов с общим списком участников, доской задач и сообщениями друг другу.

1. «Плагины → Официальные → Команды агентов»: включите сервис и перезапустите DSH.
2. В настройках проекта выберите «Команда агентов» для новых чатов и создайте чат.

Полный сценарий принят для пресета **1С Full**. В остальных пресетах запуск команды пока не проверен.

- Начинайте с одного-двух участников. В поручении указывайте цель, разрешённые пути, критерии приёмки и ограничения.
- Пишущий участник у одного родителя — один, остальные читают. Следующий writer запускается после завершения предыдущего.
- Не больше восьми участников за всё время жизни команды и восьми запусков на один ваш запрос, общих со штатными субагентами.
- Каждый результат участника заканчивается секцией `## Upstream Handoff`. Без неё стадия не засчитывается.
- ASK, виды задачи «Анализ», «Документация», «Спецификация» и штатный `/plan` запуск команды блокируют.
- Статус на доске не закрывает задачу OpenSpec. Готовность по-прежнему отмечается в `tasks.md` с доказательством.

## Задачи по расписанию

Страница **«Задачи по расписанию»** и инструменты Schedule. Кнопка **«Создать»** открывает форму: название, что сделать, папка проекта и когда запускать. Для задачи заводится отдельный чат, модель при создании не вызывается. Время в прошлом форма не примет и объяснит причину.

Задачу можно создать и из чата. Выберите вид задачи «Полный цикл» и доступ BUILD, затем попросите агента:

> По рабочим дням в 09:00 по Europe/Moscow проверь состояние проекта и подготовь короткий отчёт. Используй cron `0 9 * * 1-5`.

Бывают разовый запуск, интервал от 60 секунд, ежедневное и еженедельное расписание, cron из пяти полей. Часовой пояс для календарных расписаний задавайте явно.

- Срабатывание отправляет инструкцию в исходную сессию с её моделью и настройками.
- DSH должен быть запущен. После перезапуска просроченная разовая задача доставляется, у повторяющейся — только последнее пропущенное срабатывание.
- Паузы нет: чтобы остановить задачу, удалите её.
- «Доставлено» означает, что сообщение поставлено в сессию, а не что агент всё выполнил.

`/later`, `/check`, `/loop` и «Отправить позже» работают в своей очереди отдельно от Schedule. Отключить Schedule — «Плагины → Установленные плагины», компоненты `schedule` и `ui-schedule`.

## Доступ с телефона

**«Настройки → Доступ с телефона»** открывает тот же работающий DSH Desktop в браузере телефона: с его чатами, инструментами и подтверждениями.

1. Задайте пароль от 10 символов и сохраните.
2. Нажмите «Включить».
3. Подключите телефон к той же локальной сети или VPN, откройте показанный HTTPS-адрес или отсканируйте QR.
4. Введите пароль.

По умолчанию доступ выключен. Порт HTTPS — 3443, при конфликте выберите другой от 1024 до 65535. Сертификат самоподписанный: браузер телефона покажет предупреждение. Убедитесь, что открыли адрес своего компьютера, и разрешите переход.

Публичный туннель в интернет не создаётся, правила брандмауэра не меняются. Если адрес не открывается, проверьте сеть, выбранный адрес адаптера и разрешение DSH в брандмауэре. «Завершить все подключения» отзывает сессии и токены устройств, пароль остаётся. Пароль и токены на диск не пишутся, хранятся только их проверочные хеши.

Переключатель «Автозапуск» включает доступ при следующем запуске DSH. Само приложение при входе в Windows он не запускает.

## Telegram

**«Настройки → Telegram»**: токен бота и ваш Telegram ID как владельца. Переключатель «Подключать Telegram при запуске DSH» сохраняет выбор для следующих запусков. Токен хранится зашифрованным средствами Windows, поэтому Telegram доступен только в DSH Desktop для Windows. Сетевые настройки и настройки Telegram меняются только с компьютера, не с телефона.

Если включён [ассистент](assistent.md), переключатель «Сообщения из Telegram — ассистенту» отправляет текст из чата с ботом в его постоянный диалог. Ассистент ставит поручение в проект и отвечает, куда оно попало.

## ACP в работающем Desktop

**«Настройки → Общие → ACP» → «Включить ACP»**. Карточка показывает состояние и число клиентов, перезапуск не нужен. Скопируйте из неё конфигурацию в ACP-клиент: она запускает `dsh-1c.ps1 -AcpConnect`, локальный мост к уже открытому Desktop через именованный канал Windows. Сетевой порт не открывается, второй Harness не запускается.

Внешний агент создаёт свои сессии, ваши чаты он не захватывает. «Выключить ACP» закрывает подключённых клиентов с сохранением истории. «Включать ACP при запуске DSH» по умолчанию выключено.

Отдельный ACP-процесс без окна по-прежнему запускается как `dsh-1c.ps1 -Acp`, см. [Автономия](avtonomiya.md).

## Claude Code и Codex

DSH может отдать чат внешнему агенту по ACP. Адаптеры Claude Code и Codex уже входят в поставку, отдельно их ставить не нужно.

1. На компьютере, где запущен DSH, войдите в CLI той же учётной записью Windows. Для Claude запустите `claude` и войдите в аккаунт с подпиской Max. Для Codex выполните `codex login` и выберите вход через ChatGPT.
2. Откройте **Плагины → Внешние агенты ACP** и нажмите **Проверить снова** у нужного агента. Подсказка показывает команду для терминала. Сама панель вход не выполняет.
3. Создайте новый чат в папке проекта, выберите BUILD и нужного агента в обычном списке моделей.

Статус «протокол доступен» означает, что процесс отвечает по ACP. Он не подтверждает доступ к модели и лимиты аккаунта. Исходящий ACP работает в BUILD: внутренние инструменты внешнего процесса не дают удержать ограничения ASK и PLAN. Подтверждения инструментов DSH остаются. Остановка хода отменяет текущий запрос. Уже записанные файлы сами не откатываются. Фоновые команды Claude Code могут продолжаться после отмены.

При смене обычной модели на агента ACP откройте новый чат: контекст разных исполнителей сам не переносится. После перезапуска, если DSH предлагает восстановление, сначала используйте **Подключить исходную сессию**.

Живые аккаунты Claude и Codex при выпуске не проверялись.

## Долгие команды

**«Настройки → Долгие команды»**. Команда оболочки или операция 1С/MCP дольше заданного порога уходит в фон: можно писать агенту, пока она выполняется, а по завершении агент получает результат отдельным шагом. Порог — от 5 до 300 секунд. Перевод в фон можно выключить: тогда агент ждёт команду в том же шаге. Команда дольше защитного предела ядра всё равно уходит в фон. Фоновые шаги расходуют токены.

## Мои обращения

Пункт **«Мои обращения»** в главном меню слева: ваши обращения в поддержку, полные ответы и новое сообщение в одном окне. Ответы проверяются раз в минуту и вручную кнопкой «Обновить».

Тот же пункт есть в меню **«Настройки»** внизу левой панели. Рядом с ним **«Отзыв»**: он сразу открывает новое сообщение.

«Новое обращение» → тема и текст → «Проверить сообщение» показывает всё, что уйдёт, → «Отправить обращение». Настройки, история чатов, журналы и файлы сами не прикладываются, найденные секреты скрываются. Черновик сохраняется локально. «Подготовить уточнение» создаёт новое обращение со ссылкой на прежнее.

Нужны токен поддержки и e-mail в настройках DSH (`SUPPORT_KEY`, `SUPPORT_EMAIL`). Команды `/support` и `/supportstatus` тоже работают.

## Тикеты и Jira

В поставке есть плагин Atlassian с панелью Jira. Подключите свой аккаунт в настройках плагина. Видимая панель ещё не значит, что вход пройден.

- В карточке тикета «OpenSpec по тикету» открывает создание change с этим ключом. То же — `/opsx-propose ABC-123` или ссылкой на тикет.
- В OpenSpec у change или основной спецификации есть «Связь с тикетом»: ключ или ссылка, «Сохранить связь». Нужен BUILD.
- Связи лежат в проекте, в `openspec/tickets.json`. Формат общий с Pi, файл можно хранить в Git. Содержимое тикетов и учётные данные туда не пишутся.
- В панели **«Система учета задач»** задаётся адрес списка или фильтра проекта. «Показать открытые тикеты» загружает до 50 строк по кнопке. Выберите один тикет для привязки или до 10 для создания отдельных change.

Ссылка на тикет — только HTTP(S), без пароля и секретных параметров. Подходит не только Jira: агент читает ссылку доступным веб-инструментом, а при закрытом доступе просит текст задачи. Связь статус в Jira не меняет.

## Внешние папки

`/add-dir <путь>` подключает к текущей сессии соседнюю папку только для чтения, например общую библиотеку или другую конфигурацию. `/add-dir list` показывает подключения, `/add-dir clear` убирает. До восьми папок.

Агент читает и ищет в них отдельными инструментами. Запись туда и shell-команды с этим путём отклоняются. `.git`, профили, `.dev.env`, `.env*`, ключи и `*.1CD` закрыты. Субагенты наследуют подключения родителя. После перезапуска приложения папки подключают заново.

## Память: Cognee и OpenViking

Просмотр наборов, графа, Studio и загрузки — вкладка **«Память»** правой панели. Адреса, ключи и режим обработки — **«Настройки → 1С: инструменты → Память: Cognee и OpenViking»**. Сами серверы памяти бандл не поднимает.

| Адрес | Для чего | Пример |
|---|---|---|
| Cognee HTTP API | Проверка, наборы данных, граф | `http://127.0.0.1:8010`, без `/mcp` |
| Cognee MCP | Инструменты памяти агента, задаётся в разделе MCP | `http://127.0.0.1:8001/mcp` |
| OpenViking HTTP API | Поиск и приём файлов | `http://127.0.0.1:1933` |
| OpenViking Studio | Веб-панель сервера | `http://127.0.0.1:1933/studio` |

Сохраните адрес и нажмите «Проверить доступность»: сохранённый URL ещё не подключение. Для Cognee видны текущие наборы данных. Можно создать пустой набор, загрузить в него файл до 8 МиБ кнопкой «Загрузить и обработать» и открыть граф. Приём файла не означает, что индексация закончена.

Для OpenViking есть Studio и «Загрузить папку…». Служебные каталоги, `.env`, `.dev.env`, ключи и пути из `.gitignore` не передаются. По умолчанию загрузка идёт в режиме «Только векторы, без AI-сводок»: сервер не тратит вызовы модели на сводки каталогов. Команда `/openviking-ingest <папка>` делает то же из чата.

Вкладка читается сверху вниз. Поиск идёт по всем наборам сразу, результаты разных наборов чередуются, поэтому большой набор не вытесняет остальные. Ниже показан граф только найденного, узлы связаны с номерами результатов. **«Добавить факт»** записывает короткий факт в память. Веб-панель Cognee открывается внутри DSH. Наборы и файлы собраны в отдельном свёрнутом разделе. У OpenViking та же структура.

## Изображения в чате

Прикреплённое изображение смотрит выбранная модель чата, если у неё есть своё зрение. Отдельного плагина обработки изображений, отдельной vision-модели и кнопки зрения у поля сообщения нет.

При включённой [защите персональных данных](../zashchita-pdn.md) изображения и вложения не отправляются.

## Генерация изображений

Инструмент `image_generate` доступен во всех пресетах, отдельной командой его включать не нужно. Провайдер выбирается в вызове. В **1С Full** и в сохранённом пресете «Только 1С» скрыть генерацию для проекта можно командой `/features imageGeneration off` и вернуть `/features imageGeneration on`. Старое значение «выключено», записанное прежними версиями само, больше не действует: скрывает только эта явная команда.

## Плагины

Левое меню → **«Плагины»**: установленные компоненты, официальные плагины и создание своего. Создание собственного плагина ведёт агент в чате, с обычными подтверждениями. Свой локальный навык или плагин можно также вести командой `/local-extension`, см. [OpenSpec и знания](../openspec-i-znaniya.md).

## Лимиты моделей

Внизу левой панели, над названием сборки, видны лимиты и остатки модели открытого чата. Нажатие открывает подробности по всем аккаунтам. См. [Модели, подписки и аккаунты](../modeli-i-podpiski.md).
