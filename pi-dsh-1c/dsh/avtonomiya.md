# Автономия DSH

Цель, пульс и расписание стартуют только в BUILD. Обычные подтверждения инструментов сохраняются. Отдельного запрета менять базу у цели нет: действуют те же подтверждения, что и в обычном чате.

## Цель

Иконка **«Задать цель»** или `/goal <цель>` запускает цикл. Лимиты по умолчанию — 300 вызовов и 120 минут (`GOAL_MAX_TOOL_CALLS`, `GOAL_MAX_DURATION_MIN`). Автопродолжение — до 8 раз.

| Команда | Что делает |
|---|---|
| `/goal1c status` | Состояние |
| `/goal1c recover` | Продолжить незавершённую |
| `/goal1c stop` | Остановить |
| `/continue1c` | Только показать статус автопродолжения цели |

`/continue1c` само сообщение агенту не отправляет и кнопку продолжения не заменяет.

## Продолжить прерванный ход

Прерванный ход DSH продолжает сам. Временный сбой сети, в том числе `DeepSeek Messages transport failed`, сначала обрабатывает повтор модели. В тексте этой ошибки есть код из цепочки причин и подсказка: прокси (в том числе ответ 407), сертификат, DNS, таймаут или разрыв соединения. В Windows хост Desktop доверяет хранилищу сертификатов системы, поэтому корпоративный корневой сертификат подхватывается сам; отключить это можно переменной `NODE_USE_SYSTEM_CA=0`. Системный прокси Windows (PAC, WPAD, NTLM) DSH не читает, прокси задаётся переменной `HTTPS_PROXY`. Если ход всё же закончился ошибкой, продолжение делает не больше трёх попыток подряд, с паузами. Успешно законченный ответ сам не продолжается. Ошибки входа, баланса, неверной модели и переполнения контекста продолжение не исправляет.

Если обрывы повторяются, `/netcheck` собирает из журналов сессий за 7 дней сбои запросов к модели: время, код, этап и помог ли повтор. Затем команда проверяет сеть тем же маршрутом, что и модель: DNS, сертификат сервера, ответ API, прокси, антивирус, VPN, сон компьютера и потери сети в Windows. Отчёт сохраняется в папке `logs` рабочего каталога DSH. Ключей, текста переписки и файлов проекта в нём нет. `/netcheck журнал` разбирает только журналы. Если за эти 7 дней сбоев нет, команда так и напишет: запускайте её сразу после ошибки в том же DSH.

Отдельной кнопки «Продолжить» и переключателя у поля сообщения нет. Продолжить задачу вручную можно обычным сообщением в тот же чат. Уже созданную цель возобновляют её собственным действием.

Остановленная вами работа и старые остановленные чаты при запуске DSH сами не возобновляются. Если связь оборвалась во время действия и результат неизвестен, агенту передаётся указание сначала проверить фактическое состояние.

Уведомления об окончании, ошибке и ожидании подтверждения идут через установленный пакет уведомлений. Показ зависит от разрешений Windows.

Если модель ходит по кругу, DSH сначала повышает уровень рассуждений, затем переводит задачу на резервную модель: см. [Зацикливание](../modeli-i-podpiski.md#зацикливание). Общий бюджет токенов на чат с субагентами — кнопка [«Лимит токенов»](interfejs-i-presety.md#лимит-токенов-чата).

## Передача при заполнении контекста

Когда контекст чата заполнен до порога, DSH может передать работу новой сессии модели: краткое изложение хода сохраняется в файл, и работа продолжается с ним вместо полной истории. Карточка **«Автохандофф»** в настройках проекта: переключатель «Автохандофф — новая сессия модели» и поле «Порог заполнения контекста, %» от 17 до 100. По умолчанию включено, порог 80%. Передача делается одной попыткой, без повторов.

Вручную то же делает `/handoff`, команда есть во всех пресетах. Изложения хранятся в доме DSH, в папке `handoffs`.

Для моделей Cursor на чат держится одна сессия SDK: результат инструмента возвращается в тот же запуск, а дальше отправляется только новая часть диалога. Заполнение контекста Cursor считается без накопленного расхода прошлых запусков. Короткое ожидание, пока закроется предыдущий ход Cursor, следующий ход не останавливает. Если исход предыдущего хода не подтверждён, остановка остаётся.

## Расписание

| Команда | Что делает |
|---|---|
| `/later 5m <текст>` | Отложенное сообщение. Также секунды и часы |
| `/check 30m <текст>` | Регулярная проверка. Новая проверка только описывает, что агент сделал бы. `act <id>` включает выполнение, `observe <id>` возвращает описание, также `every`, `list`, `cancel <id>` |
| `/loop` | То же семейство циклов, с тем же наблюдением и `act` |
| `/heartbeat start\|stop\|status` | Пульс длинной сессии |
| `/sessions` | Сводка фона |

Кнопка «Отправить позже» в интерфейсе доставляет текст через `/later`.

Эти команды сами по себе модель не вызывают. Модель вызывается, когда наступает уже заданное вами время или цель.

Для календарных расписаний и cron есть отдельная страница «Задачи по расписанию»: см. [Дополнительные возможности](dopolnitelnye-vozmozhnosti.md#задачи-по-расписанию). Её задания живут в своей очереди и с `/later` и `/check` не смешиваются.

## Субагенты

Инструменты `subagent`, `subagent_fork` и `workflow`. Роли настраиваются в «Провайдеры и модели → Модели для ролей 1С». Каждый субагент заканчивает ответ секцией `## Upstream Handoff`. Без неё стадия не засчитывается. В одной пачке не больше одного пишущего.

Пачки внутри скрипта `workflow` этим счётчиком не покрыты. Кто пишет, определяется по имени и описанию запуска.

Исследовательский ход можно отдать отдельному субагенту. Произвольное смешанное сообщение само на фазы не режется.

Несколько субагентов с общей доской задач и сообщениями — «Команды агентов» (beta): см. [Дополнительные возможности](dopolnitelnye-vozmozhnosti.md#команды-агентов-beta).

Субагента можно запустить в доступе ASK и в видах задачи «Анализ», «Документация» и «Спецификация». Дочерний агент получает те же границы: в ASK и в «Анализе» он только читает, в «Документации» и «Спецификации» дополнительно правит обычные файлы Markdown внутри проекта. Во время штатного `/plan` запуск закрыт: новый субагент план не наследует, продолжение доступно после выхода из плана. Участник команды в ASK не запускается.

Модели ролей подставляются новым субагентам сразу, в том числе в открытых чатах. Список «Плагины → Субагенты → Выбор модели» сохранение ролей не меняет. См. [Служебные модели](../modeli-i-podpiski.md#служебные-модели).

## Сообщения между чатами

Независимые чаты одного запущенного DSH могут спрашивать друг друга, в том числе из разных проектов и на разных моделях. В сообщении видны отправитель и получатель, к другому чату можно перейти. Истории чатов не сливаются: в сообщение попадает только нужный контекст.

Агент находит чаты, отправляет сообщение и проверяет доставку. Обычная отправка ждёт следующего хода получателя. Уточнение работающему агенту доходит на ближайшем шаге. Неактивный сохранённый чат возобновляется. Архивированный чат сначала верните из архива.

Отправка доступна в BUILD, когда вид задачи разрешает запись. ASK, PLAN, штатный `/plan` и виды задачи только для чтения чужой чат не запускают. Список чатов и проверка доставки остаются чтением. Подтверждения инструментов у получателя свои.

Квитанция о принятии значит, что сообщение попало во входящие. Отметка, что ход получателя забрал сообщение, ещё не ответ и не конец задачи. На пару чатов — не больше десяти сообщений в минуту.

Субагенты одной команды этим путём не пользуются: у них обычные сообщения внутри команды. Плагин выключается в «Плагинах»; то же делает `ONEC_AGENT_MESSAGES=off`. После обновления сборки нужен перезапуск DSH. Между разными установками DSH и разными компьютерами такой связи нет.

## ACP

Есть два входа для внешнего агента.

**К уже открытому Desktop.** «Настройки → Общие → ACP» → «Включить ACP», затем скопируйте конфигурацию из карточки в клиент. Клиент подключается через `dsh-1c.ps1 -AcpConnect` по локальному именованному каналу, сетевой порт не открывается. Подробно — [Дополнительные возможности](dopolnitelnye-vozmozhnosti.md#acp-в-работающем-desktop).

**Отдельный процесс без окна.** Внешний клиент подключается к stdio:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\dsh-1c.ps1 -Acp
```

Поддержаны независимые сессии, задания, продолжение, события, подтверждения, отмена, сохранение и возобновление. `/acp-connect` в чате объясняет этот вход.

Поручить работу Claude Code или Codex можно из списка моделей чата, после проверки в **Плагины → Внешние агенты ACP**. Это исходящий ACP и доступен в BUILD. См. [Дополнительные возможности](dopolnitelnye-vozmozhnosti.md#claude-code-и-codex).

## Что не делегируется молча

Смена пресета, включение выключенного навыка и обход ASK/PLAN не входят в цель. Дочерний чат наследует состав исходного. Если в чате нет MCP 1С, потому что пресет «Общий» или «Разработка», цель их не включит.
