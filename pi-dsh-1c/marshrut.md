# Маршрут доработки

Один и тот же порядок в Pi и в DSH. Задачу можно написать обычным текстом: агент уже знает маршрут. В чате короткая шпаргалка — `/process1c`.

Исходники и информационная база — разные состояния. Пока вы не подтвердили загрузку, правка файлов базу не меняет.

| Шаг | Что сделать | Результат |
|---|---|---|
| 1. Открыть проект | Запустить поставку и выбрать папку выгрузки, не папку бандла | Видны проект, параметры базы, модель, MCP и OpenSpec |
| 2. Выбрать модель | Вход по подписке или ключу, затем модель. См. [Модели, подписки и аккаунты](modeli-i-podpiski.md) | Запросы уходят в выбранную модель. Наличие CLI само по себе входом не считается |
| 3. Выбрать вид задачи и доступ | [Режимы](rezhimy.md) | Видно, это полный цикл, фикс, документация, спецификация или анализ, и можно ли писать файлы |
| 4. Оформить изменение | OpenSpec для нетривиальной доработки | Есть proposal, сценарии, design и задачи. Мелкий вопрос и мелкая правка change не требуют |
| 5. Дать знания | Факт или правило о конфигурации | Запись сначала черновик. В работу она попадает только после вашего apply или approve |
| 6. Найти объект | Сформулировать задачу по-русски | Агент ищет объект, процедуру и связи через MCP, затем читает нужный фрагмент |
| 7. Реализовать | Обычный запрос или применение change | BSL меняется точечно. Метаданные — навыком, не ручной правкой XML |
| 8. Проверить | BSL Language Server, загрузка в тестовую базу, журнал, снимок формы | Синтаксис проверен локально. Поведение в базе — отдельным шагом |
| 9. Сдать | Закрыть задачи change с доказательством, собрать `.cf` или `.cfe` | В `build/` лежит бинарник, а не копия XML. Change закрыт |
| 10. Запомнить | Урок, ретроспектива, улучшение навыка | Повторный приём сохранён только после вашего подтверждения |

Пример постановки:

> В расширении проверять заполнение договора перед проведением документа «Заказ». Сначала найди объект и существующие проверки через MCP, оформи OpenSpec, внеси минимальную правку и проверь. Загрузку в базу сделаем отдельно.

Для такой задачи нельзя угадывать имя объекта, обработчик проведения и формат выгрузки: их устанавливают инструментами.

Если в Pi не подтверждены все семь обязательных MCP, чтение, план, правки файлов и скрипты навыков продолжаются: недоступны только инструменты молчащих серверов. В DSH то же для файлов, но смысловая правка метаданных через MCP закрыта, пока нет обязательного сервера или индекс устарел. Не называйте разработку проверенной, пока нужные серверы и выбранная база не ответили.

То, что свежесть выгрузки относительно живой базы ещё ни разу не сверялась, предупреждением не считается и само по себе не подтверждает актуальность файлов. Предупреждение появляется, когда сверка есть и показывает проблему. В Pi это «Выгрузка 1С устарела относительно живой базы». В DSH — выгрузка старее подтверждённого изменения базы, помечена как частичная или относится к другой базе. Обновляют её командой `/sync1c`.
