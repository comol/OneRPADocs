# Получение и обновление

## Где взять

Бандлы описаны на странице [vibecoding1c.ru/harnesses](https://vibecoding1c.ru/harnesses). После покупки архивы доступны в личном кабинете сайта: там же ссылка на папку с актуальными выпусками. В эту папку выкладываются только ZIP-архивы, без отдельных инструкций.

MCP-серверы 1С — отдельный продукт со своим дистрибутивом `MCP_Distr`, см. [MCP серверы для 1С](../mcp-servery-1c/README.md).

## Какой архив выбрать

В имени архива есть продукт, версия бандла, дата и время выпуска, платформа:

| Архив | Что внутри |
|---|---|
| `Pi-1C-Bundle-<версия>-<выпуск>-client-win-x64.zip` | Pi для Windows x64 |
| `Pi-1C-Bundle-<версия>-<выпуск>-client-linux-x64.zip` | Pi для Linux x64 |
| `Pi-1C-Bundle-<версия>-<выпуск>-client-darwin-arm64.zip` | Pi для macOS на Apple Silicon |
| `DSH-Desktop-1C-<версия>-<выпуск>-win-x64.zip` | DSH Desktop для Windows x64 |
| `DSH-Web-1C-<версия>-<выпуск>-linux-x64.zip` | DSH Web для Linux x64 |
| `DSH-Desktop-1C-<версия>-<выпуск>-darwin-arm64.zip` | DSH Desktop для macOS на Apple Silicon |

Выпуск — дата и время сборки в виде `ГГГГММДД-ЧЧММСС`. Чем больше число, тем новее архив. Актуальные опубликованные поставки: Pi — бандл **1.1.0**, ядро **1.5.0**; DSH — бандл **0.1.0**, официальный Desktop **0.2.2-rc.1**. Установка описана в разделах [Pi](pi/ustanovka-i-zapusk.md), [DSH Desktop](dsh/ustanovka-i-zapusk.md) и [Linux и macOS](platformy.md).

## Обновление из приложения

Обе поставки сами проверяют ту же папку выпусков: при запуске, не чаще раза в сутки, и затем раз в сутки во время работы. Закрытое приложение ничего не проверяет, запуск сеть не задерживает и модель не вызывает.

| | Pi 1C | DSH 1С |
|---|---|---|
| Проверить и обновить | `/app-update` | Меню приложения → «Обновление бандла…» |
| Проверить сейчас, без загрузки | `/app-update check` | «Обновление бандла…»: архив загружается только по кнопке «Скачать» |
| Последний результат | `/app-update status` | То же окно |

Загрузка и установка — два отдельных согласия. Сначала бандл показывает имя и размер архива и спрашивает, скачивать ли его. Архив проверяется по размеру, SHA-256, продукту и составу. Затем отдельно спрашивается установка с перезапуском. Ответ «Позже» или «Нет» оставляет работу открытой, подготовленная версия сохраняется.

При установке приложение закрывается, файлы поставки заменяются, приложение открывается снова. Pi в терминале возвращается в тот же проект и сессию. Настройки, вход, история, проекты и локальные расширения сохраняются. Если замена не удалась, возвращаются прежние файлы.

Перед согласием сохраните правки и дождитесь нужных задач. В Pi Web перезапуск прервёт ответы во всех вкладках этого сервера. Другие открытые копии Pi из той же папки закройте заранее: обновление их не завершает принудительно.

Обновление выбирает только архив того же продукта, варианта, ОС и архитектуры.

## Ручное обновление

Выпуск без встроенного обновления, повреждённая установка или переход на другую машину — ручной путь:

1. Закройте приложение. DSH — через выход из значка в трее.
2. Распакуйте новый ZIP в **новую** папку, не поверх старой.
3. Pi в Windows: выполните `Pi-1C.exe --install -SkipMcpProbe` в новой папке.
4. Запустите новую поставку и проверьте вход, проекты и историю.
5. Только после этого удалите старую папку.

Состояние Pi лежит вне поставки и подхватывается новой версией само. Путь печатает `Pi-1C.exe --settings`. У DSH Desktop профили, история и ключи лежат в папке поставки: `.dsh-1c/home` и `.desktop-local`. При ручном переходе на новую папку их нужно перенести.

## Правила 1С и MCP-серверы

Обновление поставки не трогает Docker-образы MCP и не подменяет правила 1С молча.

- Pi: `/bundle-updates` проверяет новые правила и MCP при старте и раз в сутки (`now`, `status`, `on`, `off`, `interval <часы>`). `/checkupdates` и `/updaterules` показывают источник правил и порядок обновления, `/updatemcp` — порядок обновления серверов.
- DSH: `/lifecycle updates` проверяет правила и MCP, `/lifecycle updates apply rules` применяет правила.

Образы MCP обновляются по разделу [MCP серверы для 1С](../mcp-servery-1c/README.md).

## Удаление

Обе поставки не требуют прав администратора и ничего не регистрируют в системе, кроме пользовательской команды `startpi1c` у Pi.

- **Pi.** Удалите папку поставки. Каталог состояния с логином и историей останется: путь печатает `Pi-1C.exe --settings`, удалите его вручную, если история не нужна. Команда `startpi1c` лежит в `Programs\Pi1C\bin` профиля пользователя и прописана в пользовательский PATH.
- **DSH.** Выйдите из приложения через трей и удалите папку поставки. Если нужны профили и история, сначала сохраните `.dsh-1c/home` и `.desktop-local`.

Исходники проектов и их `.dev.env` лежат отдельно и при удалении поставки не трогаются.
