# Получение и обновление

## Где взять

Бандлы описаны на странице [vibecoding1c.ru/harnesses](https://vibecoding1c.ru/harnesses). После покупки архивы доступны в личном кабинете сайта: там же ссылка на папку с актуальными выпусками. В эту папку выкладываются только ZIP-архивы, без отдельных инструкций.

MCP-серверы 1С — отдельный продукт со своим дистрибутивом `MCP_Distr`, см. [MCP серверы для 1С](../mcp-servery-1c/README.md).

## Какой архив выбрать

В имени архива есть продукт, версия бандла, дата и время выпуска, платформа:

| Архив | Что внутри |
|---|---|
| `Pi-1C-Bundle-<версия>-<выпуск>-client-win-x64.zip` | Pi для Windows x64 |
| `Pi-1C-Bundle-<версия>-<выпуск>-client-linux-x64.zip` | Pi для Linux x64 |
| `Pi-1C-Bundle-<версия>-<выпуск>-client-darwin-arm64.zip` | Pi для macOS на Apple Silicon |
| `DSH-Desktop-1C-<версия>-<выпуск>-win-x64.zip` | DSH Desktop для Windows x64 |
| `DSH-Web-1C-<версия>-<выпуск>-linux-x64.zip` | DSH Web для Linux x64 |
| `DSH-Desktop-1C-<версия>-<выпуск>-darwin-arm64.zip` | DSH Desktop для macOS на Apple Silicon |

Выпуск — дата и время сборки в виде `ГГГГММДД-ЧЧММСС`. Чем больше число, тем новее архив. Актуальные опубликованные поставки: Pi — бандл **1.1.0**, ядро **1.5.0**; DSH — бандл **0.1.0**, официальный Desktop **0.2.2-rc.2**. Выпуски DSH выходят часто, поэтому ориентируйтесь на дату в имени архива. Установка описана в разделах [Pi](pi/ustanovka-i-zapusk.md), [DSH Desktop](dsh/ustanovka-i-zapusk.md) и [Linux и macOS](platformy.md).

## Что вошло в выпуск 07.11.2026

Общее для Pi и DSH: правила 1С обновлены до свежей версии, в том числе заимствование в расширениях (`cfe-borrow`) теперь следует поведению Конфигуратора на колонках, ссылочных типах и отсутствующих экспортах.

**Pi.** Ядро обновлено до 1.5.0. Сообщение пользователя ставит активную цель на паузу, продолжение — командой `/goal-resume`. В архивы для Linux и macOS вошли инструкции своей системы с командами `./Pi-1C`.

**DSH.** Ядро и Desktop обновлены до 0.2.2-rc.1, полный список изменений ядра — в [официальных заметках к выпуску](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.1). Исправления сборки:

- панель «Лимиты провайдеров» видит вход через DeepSeek Account, баланс с длинной дробной частью больше не теряется;
- каскад резервных моделей срабатывает на ответ 402 «Insufficient account funds»;
- на маршрутах-посредниках смена модели не роняет запрос из-за подписи `thinking`, уведомление о смене модели показывается один раз, недоступная модель (403) не запрашивается на каждом шаге;
- сообщение проверки качества больше не срывает ход ошибкой `lacks an identified message`, а удалённый файл не держит проверку завершения;
- отменённая сетевая запись `write ECANCELED` не завершает хост, адаптер Cursor сообщает об ошибке сети;
- файл `icon.svg` входит в поставку, ошибки метаданных пакета на странице плагинов нет.

## Что изменилось после 07.11.2026

На Windows агент, правя метаданные по просьбе:

- переносит уже существующий реквизит того же объекта из прежней выгрузки и сохраняет его идентификатор. Отказ происходит до записи. Повтор такого же переноса ничего не пишет. Если проверка метаданных не прошла, файл остаётся как был;
- регистрирует уже готовую форму у владельца и не переписывает её файлы, не меняет идентификатор и не трогает слот основной формы. Повторная регистрация ничего не делает;
- у поля ввода на форме формата 8.5 можно включить или выключить автоматический режим редактирования (`AutoEditMode`). На формах более старого формата этот режим не записывается.

Эти три операции есть в правилах для Windows. В скриптах для Linux и macOS их пока нет. `/meta-apply` по-прежнему только план, не запись.

В DSH выгрузка, загрузка и проверка запуска, порученные из чата, в BUILD идут без отдельного окна подтверждения бандла. Обычные подтверждения других инструментов и режимы ASK/PLAN/BUILD остаются. Окно деплоя можно открыть вручную: кнопка «Загрузить» в панели Конфигуратора по-прежнему спрашивает подтверждение.

Обновление из приложения в Pi и DSH больше не срывается из-за слишком частых запросов к серверу. Обновление DSH больше не делает все уже созданные сессии недоступными.

## Что вошло в выпуски 11–13.11.2026

С 13.11.2026 новые возможности появляются только в DSH. Pi остаётся на поддержке: в нём исправляются критичные дефекты, когда Pi не запускается, не ставится или не обновляется, теряет данные, раскрывает секреты или ломает основной сценарий. Новый выпуск Pi выходит только после такого исправления.

**Общее для Pi и DSH.**

- Правила 1С обновлены. Добавлено общее правило выгрузки и загрузки конфигурации, уточнены профили Graph MCP и перезапуск сценариев тонкого клиента в QA MCP 0.8.0 и новее.
- Команда `/check-edt` проверяет подключение к EDT-MCP: версию EDT и список её проектов. См. [MCP в Pi и DSH](mcp.md#edt-mcp).
- Зацикливание модели обнаруживается само: сначала повышается уровень рассуждений, затем задача переходит на резервную модель. См. [Модели, подписки и аккаунты](modeli-i-podpiski.md#зацикливание).

**DSH.** Ядро и Desktop обновлены до 0.2.2-rc.2.

- Архив стал меньше: для Windows около 0,9 ГБ вместо 1,5 ГБ. Исполнители Claude Code и Codex для ACP и четыре модели персонажа Moon Rabbit в него не входят. Исполнители скачиваются при первом включении, модели персонажа подключаются из архива автора. См. [Claude Code и Codex](dsh/dopolnitelnye-vozmozhnosti.md#claude-code-и-codex) и [Персонаж](dsh/assistent.md#персонаж).
- Проверка завершения хода следит только за файлами `.bsl` и `.xml`.
- В BUILD агент сам загружает изменение в выбранную базу и проверяет его, в том числе повторно после исправления ошибки. См. [Проверка, откат и сдача](dsh/proverka-otkat-sdacha.md#загрузка-в-базу).
- Кнопка «Лимит токенов» в строке ввода задаёт общий бюджет на чат вместе с субагентами. См. [Интерфейс и пресеты](dsh/interfejs-i-presety.md#лимит-токенов-чата).
- В меню моделей есть избранное, пункт «Свой провайдер · совместимый API» и одна строка ошибок загрузки с кнопками «Повторить» и «Скрыть». Инструкции к модели подбираются по выбранной модели. См. [Модели, подписки и аккаунты](modeli-i-podpiski.md).
- При заполнении контекста чат может сам передать работу новой сессии модели («Автохандофф»), вручную — `/handoff`. Для Cursor на чат держится одна сессия SDK. См. [Автономия](dsh/avtonomiya.md#передача-при-заполнении-контекста).
- Ассистент: картинка в чат персонажа, «Капля» поверх других окон, озвучка ответа и текст вопроса в уведомлении. См. [Ассистент DSH](dsh/assistent.md).
- Для форм и макетов: переход к обработчику элемента формы, адрес ячейки макета в черновике, сравнение формы с последним коммитом, замечания к строкам `.mdo` EDT. `/receipt` показывает сценарии из свежего отчёта JUnit. См. [Проверка, откат и сдача](dsh/proverka-otkat-sdacha.md).
- Пресеты «Общий» и «Разработка» работают на штатной системной инструкции DeepSeek Harness, MCP в этих чатах не участвуют. См. [Интерфейс и пресеты](dsh/interfejs-i-presety.md#пресеты).
- Ошибка `DeepSeek Messages transport failed` показывает код и понятную причину: прокси, сертификат, DNS, таймаут или разрыв. В Windows хост Desktop доверяет хранилищу сертификатов системы.
- Текст длиннее 50 000 символов, вставленный в поле сообщения, прикрепляется файлом «вставка.txt», чтобы поле не зависло.
- Большая выгрузка EDT открывается в дереве метаданных упрощённым деревом, подробности подгружаются при раскрытии.
- Токен сервера QA можно задать как `ONEC_MCP_QA_TOKEN` или `QA_HTTP_TOKEN`. См. [MCP в Pi и DSH](mcp.md#серверы-поставки).

## Обновление из приложения

Обе поставки сами проверяют ту же папку выпусков: при запуске, не чаще раза в сутки, и затем раз в сутки во время работы. Закрытое приложение ничего не проверяет, запуск сеть не задерживает и модель не вызывает.

| | Pi 1C | DSH 1С |
|---|---|---|
| Проверить и обновить | `/app-update` | Меню приложения → «Обновление бандла…» |
| Проверить сейчас, без загрузки | `/app-update check` | «Обновление бандла…»: архив загружается только по кнопке «Скачать» |
| Последний результат | `/app-update status` | То же окно |

Загрузка и установка — два отдельных согласия. Сначала бандл показывает имя и размер архива и спрашивает, скачивать ли его. Архив проверяется по размеру, SHA-256, продукту и составу. Затем отдельно спрашивается установка с перезапуском. Ответ «Позже» или «Нет» оставляет работу открытой, подготовленная версия сохраняется.

При установке приложение закрывается, файлы поставки заменяются, приложение открывается снова. Pi в терминале возвращается в тот же проект и сессию. Настройки, вход, история, проекты и локальные расширения сохраняются. Если замена не удалась, возвращаются прежние файлы.

Перед согласием сохраните правки и дождитесь нужных задач. В Pi Web перезапуск прервёт ответы во всех вкладках этого сервера. Другие открытые копии Pi из той же папки закройте заранее: обновление их не завершает принудительно.

Обновление выбирает только архив того же продукта, варианта, ОС и архитектуры.

## Ручное обновление

Выпуск без встроенного обновления, повреждённая установка или переход на другую машину — ручной путь:

1. Закройте приложение. DSH — через выход из значка в трее.
2. Распакуйте новый ZIP в **новую** папку, не поверх старой.
3. Pi в Windows: выполните `Pi-1C.exe --install -SkipMcpProbe` в новой папке.
4. Запустите новую поставку и проверьте вход, проекты и историю.
5. Только после этого удалите старую папку.

Состояние Pi лежит вне поставки и подхватывается новой версией само. Путь печатает `Pi-1C.exe --settings`. У DSH Desktop профили, история и ключи лежат в папке поставки: `.dsh-1c/home` и `.desktop-local`. При ручном переходе на новую папку их нужно перенести.

## Правила 1С и MCP-серверы

Обновление поставки не трогает Docker-образы MCP и не подменяет правила 1С молча.

- Pi: `/bundle-updates` проверяет новые правила и MCP при старте и раз в сутки (`now`, `status`, `on`, `off`, `interval <часы>`). `/checkupdates` и `/updaterules` показывают источник правил и порядок обновления, `/updatemcp` — порядок обновления серверов.
- DSH: `/lifecycle updates` проверяет правила и MCP, `/lifecycle updates apply rules` применяет правила.

Образы MCP обновляются по разделу [MCP серверы для 1С](../mcp-servery-1c/README.md).

## Удаление

Обе поставки не требуют прав администратора и ничего не регистрируют в системе, кроме пользовательской команды `startpi1c` у Pi.

- **Pi.** Удалите папку поставки. Каталог состояния с логином и историей останется: путь печатает `Pi-1C.exe --settings`, удалите его вручную, если история не нужна. Команда `startpi1c` лежит в `Programs\Pi1C\bin` профиля пользователя и прописана в пользовательский PATH.
- **DSH.** Выйдите из приложения через трей и удалите папку поставки. Если нужны профили и история, сначала сохраните `.dsh-1c/home` и `.desktop-local`.

Исходники проектов и их `.dev.env` лежат отдельно и при удалении поставки не трогаются.
