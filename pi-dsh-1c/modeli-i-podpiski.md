# Модели, подписки и аккаунты

Модель выбираете вы. В архиве поставки нет ключей и готовых входов. Пароли и ключи вводятся в окнах входа и настроек, не в текст чата и не в аргументы команд.

Платный Anthropic API не используется. Claude подключается только подпиской Max через официальный Claude Code.

## Где подключать

| | Pi 1C | DSH 1С |
|---|---|---|
| Вход и выбор модели | `/login` (то же `/provider`, `/connect`), затем `/model`. В окне входа два пункта: «Подписки / OAuth» и «API — нужен ключ» | «Настройки → Модели и подписки» или «Подключить модель ▾» |
| Несколько аккаунтов | `/accounts` | «Модели и подписки», раздел аккаунтов провайдера |
| Основная и резервные модели | `/model-fallback` | «Модели и подписки → Основная и резервные модели» |
| Остатки и лимиты | `/quota` в футере | Индикатор внизу левой панели |
| Модели без секретов | `/model` | `/models1c`, `dsh-1c.ps1 -Models` |

В Pi Web список моделей показывает всех провайдеров поставки. У провайдера без входа стоит «Подключить»: кнопка открывает вход именно этого провайдера.

## Что можно подключить

| Провайдер | Как подключается | Оговорка |
|---|---|---|
| Claude | Подписка Max через официальный Claude Code. В Pi — `/claude-login` | Нужен установленный CLI `claude`. Наличие CLI само по себе не вход |
| Cursor | Действующая подписка через официальный SDK. В Pi — `/cursor-login`, затем `/cursor-refresh-models` | Вход в приложение Cursor сессию бандла не авторизует |
| OpenAI | Подписка ChatGPT / Codex или API-ключ | Подписка и API-ключ — разные подключения |
| GitHub Copilot | Подписка Copilot | |
| Grok (xAI) | Подписка SuperGrok или X Premium, вход по коду в браузере | Доступ зависит от тарифа |
| Kimi Code | Подписка Kimi Code, вход через браузер | API-ключ не нужен |
| GLM (Z.AI) | Ключ тарифа **Coding Plan** | Обычный облачный ключ тариф не заменяет |
| Qwen (Alibaba) | Ключ тарифа **Coding Plan** | Token Plan с оплатой токенов — другой продукт |
| Google Gemini | Личный вход через официальный Antigravity CLI | Работает только в доступе BUILD |
| Meta Muse | Личный вход через официальный Muse CLI | Интерфейс экспериментальный |
| OpenCode Go | Подписка Go, ключ из консоли провайдера | Включённый в консоли **Extra Usage** может тратить платный баланс сверх подписки |
| OpenCode Zen | Оплата по использованию | Это не фиксированная подписка |
| DeepSeek | API-ключ, в DSH также вход DeepSeek Account | Ключ можно задать переменной `DEEPSEEK_API_KEY` |
| Другие API | Ключ провайдера, например OpenRouter или RouterAI | Оплата по тарифу провайдера |

В DSH раздел «Другие API» стоит в списке провайдеров первым. Сервис с OpenAI-совместимым API, которого нет в списке, подключается пунктом **«Свой провайдер · совместимый API»**: адрес, ключ и модели задаются в форме «Свой API моделей», в ней есть пример для Ollama Cloud (`https://ollama.com/v1`).

Официальные CLI Google и Muse в архив не входят. При первом подключении бандл скачивает закреплённую версию и проверяет её целостность. Нужны интернет и место на диске. В Pi CLI можно подготовить заранее: `/subscriptions setup`.

Покупка подписки, доступность тарифа в вашем регионе и вход — на стороне владельца аккаунта. Проверки поставки выполнялись на тестовых данных, без настоящих аккаунтов и списаний.

{% hint style="info" %}
В Pi есть режим только бесплатных моделей: `/toggle-free`. Бесплатный маршрут всё равно требует аккаунта и ключа провайдера, лимиты задаёт провайдер.
{% endhint %}

## Несколько аккаунтов одного провайдера

Можно подключить несколько своих аккаунтов одного провайдера, дать им имена, выбрать основной, задать порядок резервных и выключить ротацию.

Если основной аккаунт упёрся в лимит, потерял вход или временно недоступен, бандл берёт следующий аккаунт **того же провайдера, той же модели и того же способа входа**. Подписка не подменяется платным API. OAuth сначала пробует штатное обновление входа. Ошибочный аккаунт получает паузу: в Pi по заголовку `Retry-After`, иначе 60 секунд, при сетевом сбое 15 секунд.

Ротация — это запасной путь при сбое, а не чередование аккаунтов на каждом запросе. Она не увеличивает квоты: общий лимит организации может действовать на все её аккаунты.

Переключение возможно только до начала ответа. Уже начатый текст, рассуждения и вызовы инструментов заново не выполняются. Ошибка самого запроса и переполнение контекста сменой аккаунта не лечатся.

## Основная и резервные модели

Цепочка задаёт основную модель и упорядоченные резервные, в том числе у других провайдеров и на других аккаунтах. В Pi — до семи резервов, в DSH — до восьми.

1. Выберите область: текущий чат или новые чаты.
2. Задайте основную модель: провайдер, модель, аккаунт. Вариант «автоматически» использует ротацию аккаунтов.
3. Добавьте резервы и расставьте их по порядку.
4. Включите резервирование и сохраните цепочку.

При сбое входа, лимите, временной ошибке сети или недоступной модели сначала перебираются аккаунты основной модели, затем резервы по порядку. Каждый новый запрос снова начинается с основной модели. Переход на другой способ оплаты возможен только через явно выбранный вами резерв.

Ручной выбор другой модели приостанавливает цепочку. Чтобы вернуть её, выберите основную модель цепочки снова. Без цепочки поведение обычное: одна выбранная модель, скрытых резервов нет.

### Зацикливание

Pi и DSH следят, не ходит ли модель по кругу. Три шага подряд с одинаковыми результатами инструментов или одной и той же ошибкой повышают уровень рассуждений, если модель его поддерживает. Если цикл продолжается, задача переходит на следующую модель цепочки вместе с историей вызовов инструментов. Когда резервы закончились, ход останавливается, а активная цель отмечается как заблокированная.

Отдельная модель-наблюдатель не нужна: используется та же цепочка основной и резервных моделей. Новое сообщение снова начинается с основной модели. Повтор одного и того же смысла разными словами и зависание потока так не обнаруживаются.

## Меню моделей в DSH

Звезда у модели — «Добавить в избранное». Переключатель над списком показывает «Избранное» или «Все модели», поиск работает в обоих. Отметки хранятся отдельно для каждой пары «провайдер + модель» и сохраняются после перезапуска. У Cursor отметка относится к семейству модели и не зависит от уровня рассуждений.

Если каталог какого-то провайдера не загрузился, над списком одна строка «Не загрузились: …» с кнопками «Повторить» и «Скрыть». Модели Claude Code и Codex появляются в списке после того, как их исполнитель скачан и проверен: см. [Claude Code и Codex](dsh/dopolnitelnye-vozmozhnosti.md#claude-code-и-codex).

## Инструкции под модель

DSH добавляет к системной инструкции короткие правила из официальных руководств к выбранной модели или её семейству. Для Claude Fable, например, модель коротко называет следующее действие и сообщает о ходе работы, а список дел доступен и в задачах анализа, документации и спецификации. Профиль подбирается к модели текущей попытки: при смене модели в чате и при переходе на резерв он меняется со следующего запроса. Для моделей без своего профиля действуют общие правила.

Настройка проекта «Профиль правил модели» (`AGENT_MODEL` в «Настройки проекта 1С»): пусто — профиль по фактической модели, `off` — профили выключены. Значения `opus5`, `sonnet5`, `fable5`, `gpt56` и `gpt6` задают профиль на случай, когда модель не распознана.

## Лимиты и остатки

В DSH индикатор внизу левой панели показывает лимит модели открытого чата: окна расхода и время сброса, остатки денежного баланса там, где провайдер их отдаёт. У OpenCode Go это окна «5 часов», «Неделя» и «Месяц»; если ключ отклонён, вместо нулей показано «нет данных». Нажатие открывает все аккаунты и провайдеры. Баланс кэшируется на пять минут. Для провайдеров без подтверждённого источника данных значение не показывается, а не выводится нулём. Бандл не делает платный запрос ради проверки лимита.

В Pi квоты провайдеров показывает `/quota` в футере, расход токенов текущей сессии — `/usage`.

## Служебные модели

Определение вида задачи и поиск можно отдать дешёвой модели. В Pi — `/service-models`, в DSH — поля «Модель определения типа задачи» и «Модель поиска». Пустое значение в DSH означает самую дешёвую совместимую модель из уже подключённых. Служебная модель не меняет выбранный вами вид задачи и права ASK/PLAN/BUILD.

Модели для ролей субагентов настраиваются отдельно: в Pi — `/roles` и `/subagents`, в DSH — в «Моделях и подписках».
