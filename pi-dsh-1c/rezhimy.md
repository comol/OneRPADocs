# Режимы

В обоих бандлах четыре независимые настройки. Они не подменяют друг друга. Выбор действует в текущей сессии и сохраняется при её продолжении.

| Настройка | Pi | DSH Desktop | По умолчанию |
|---|---|---|---|
| Вид задачи | `/mode full\|bugfix\|doc\|spec\|analysis` | `/taskmode auto\|doc\|spec\|analysis\|bugfix\|full`. Старый `/quality` — то же, не глубина | В Pi `full`. В DSH `auto`: по запросу |
| Глубина проверок | `/quality` или `/sdlc` `lite\|standard\|full` | `/sdlc lite\|standard\|full` | `standard` |
| Оркестрация | `/economymode standard\|economy` | `/economymode standard\|economy` | `standard` |
| UI-тесты | `/uitests on\|manual\|off` | `/uitests on\|manual\|off` | В Pi смотрите `/uitests status`; в DSH по умолчанию `manual` |
| Доступ к записи | `/access ask\|plan\|build` | `/mode ask\|plan\|build` | В DSH обычно BUILD (`ONEC_MODE_DEFAULT`) |

Без аргумента команда открывает выбор. `status` показывает текущее значение.

## Вид задачи

- **full** — полный цикл: понять, описать, сделать, проверить.
- **bugfix** — быстрый фикс.
- **doc** — документация. В Pi запись ограничена файлами Markdown.
- **spec** — спецификация без реализации. В Pi это плановый доступ.
- **analysis** — только чтение и ответ.

Риск задачи может потребовать полного цикла даже если вы начали с короткого запроса. Вид задачи не снимает ограничения доступа.

## Доступ ASK / PLAN / BUILD

- **ASK** — только чтение и ответы.
- **PLAN** — запись только в `openspec/` и черновики знаний. Произвольный shell выключен.
- **BUILD** — полная работа в пределах вида задачи и общих ограничений.

В Pi права задаёт `/access`. Вызов `/mode ask|plan|build` принимается как совместимый вход в `/access`, но `/mode status` показывает вид задачи, а не права.

В DSH права задаёт `/mode`. `/profile explore|plan|build` — совместимый алиас. Вид задачи там не называется `/mode`.

## Глубина, оркестрация и UI-тесты

`/sdlc` — это глубина проверок, а не усилие модели. Команда не переключает UI-тесты.

`standard` оркестрации использует выбранную модель чата и уже настроенные модели помощников. `economy` расширяет делегирование на более дешёвые модели, но не подменяет вход и лимиты подписки.

`/uitests on` запускает проверки интерфейса автоматически, `manual` — по запросу, `off` — выключает их. В DSH значение `on` соответствует `auto` в `.dev.env`.

## Подтверждения

Обычные подтверждения инструментов сохраняются. Отдельного режима «база только для чтения» нет: загрузка исходников в информационную базу и другие изменения базы требуют явного инструмента и вашего подтверждения, и только в BUILD.

В Pi YOLO-подтверждения по умолчанию включены. `YOLO_MODE=off` выключает их на старте. В DSH тот же ключ влияет на пресет прав нового чата: при `off` и без явного пресета берётся штатный `workspace-write` с подтверждением.
