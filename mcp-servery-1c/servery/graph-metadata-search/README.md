# Graph Metadata Search

Графовый поиск по метаданным конфигурации 1С через Neo4j.

## Назначение

Graph Metadata Search строит граф связей метаданных вашей конфигурации 1С. ИИ начинает понимать, как объекты связаны между собой, а не просто видит их названия.

## Возможности

ИИ получает инструменты для:

- Анализа связей документов, регистров, справочников
- Нахождения зависимостей
- Объяснения архитектуры конфигурации
- Ответов на вопросы в терминах бизнес-сущностей

## Примеры использования

- "Какие регистры использует документ Реализация?"
- "Покажи все объекты, связанные со справочником Контрагенты"
- "Какая структура модуля документа Заказ?"
- "Какие формы есть у справочника Номенклатура?"

## Особенности

- Использует **Neo4j** для хранения графа
- Понимает связи между объектами
- Особенно полезен для больших/чужих конфигураций
- Требует docker-compose для запуска
- **Веб-интерфейс Neo4j Browser** для визуализации графа: `http://localhost:7474`
- **Веб-интерфейс поиска**: `http://localhost:8006/search`

## Доступные инструменты MCP

ИИ получает следующие инструменты:

| Инструмент | Описание |
|------------|----------|
| `search_metadata` | Поиск объектов метаданных по имени или описанию (требует OpenAI API) |
| `get_metadata_prompt` | Получение схемы БД Neo4j и примеров Cypher-запросов |
| `execute_metadata_cypher` | Выполнение произвольного Cypher-запроса к графу метаданных |
| `answer_metadata_question` | Ответ на вопросы о метаданных на естественном языке (требует OpenAI API) |
| `business_search` | Семантический поиск по бизнес-описаниям объектов метаданных |
| `search_code` | Поиск по BSL-коду модулей (полнотекстовый, семантический, гибридный) |

### search_metadata

Поиск объектов метаданных 1С по имени, описанию или любым известным атрибутам. Использует LLM для генерации Cypher-запроса. Имена объектов обычно на русском языке. Поддерживает поиск связанных объектов, нескольких объектов, объектов с определёнными реквизитами.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `query` | string | Описание искомых объектов метаданных и их атрибутов |

**Возврат**: Отформатированная строка с результатами поиска, объекты разделены `---`.

> Требует доступ к OpenAI API. При отсутствии API предлагает использовать `execute_metadata_cypher` или `get_metadata_prompt`.

### get_metadata_prompt

Возвращает описание схемы базы данных Neo4j и примеры Cypher-запросов. Используется для самостоятельного составления запросов к графу метаданных.

Параметры отсутствуют.

**Возврат**: Строка со схемой БД и примерами запросов.

### execute_metadata_cypher

Выполняет Cypher-запрос напрямую к базе данных Neo4j с метаданными. Используйте совместно с `get_metadata_prompt` для получения схемы.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `query` | string | Cypher-запрос для выполнения |

**Возврат**: JSON-строка с результатами запроса или сообщение об ошибке.

### answer_metadata_question

Отвечает на вопросы о метаданных на естественном языке. Вопросы принимаются на русском и английском языках.

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `question` | string | — | Вопрос о метаданных |
| `max_tokens` | int | 4000 | Максимальное количество токенов для ответа LLM |
| `include_code` | bool | true | Включать ли фрагменты кода в контекст |

**Возврат**: Структурированный ответ с источниками, количеством использованных токенов и оценкой уверенности.

> Требует доступ к OpenAI API.

### business_search

Семантический поиск объектов метаданных по описанию бизнес-функциональности. Использует векторный индекс по документации.

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `query` | string | — | Описание искомой функциональности на естественном языке |
| `top_k` | int | 10 | Максимальное количество результатов |
| `filter_type` | string | — | Фильтр по категории метаданных (например, `Справочники`, `Документы`) |

**Возврат**: Ранжированные результаты с оценками релевантности и бизнес-контекстом.

> Требует включения `enable_business_search` в конфигурации. При недоступности векторного индекса автоматически переключается на полнотекстовый поиск Neo4j.

### search_code

Поиск по BSL-коду во всех объектах метаданных. Поддерживает полнотекстовый, семантический и гибридный режимы поиска.

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `query` | string | — | Имя функции, ключевое слово или описание на естественном языке |
| `search_type` | string | `hybrid` | Тип поиска: `fulltext` (точное совпадение), `semantic` (по смыслу), `hybrid` (оба) |
| `top_k` | int | 3 | Максимальное количество результатов на каждый тип поиска (в режиме `hybrid` — до 6 итого) |
| `filter_type` | string | — | Фильтр по категории метаданных (например, `Справочники`, `Документы`, `ОбщиеМодули`) |

**Возврат**: Результаты поиска с фрагментами кода и оценками релевантности.

**Примеры**:
- `search_code("ПроверитьЗаполнение")` — поиск по имени функции (fulltext)
- `search_code("расчет скидки", search_type="semantic")` — поиск по назначению
- `search_code("Процедура AND Скидк*", search_type="fulltext")` — синтаксис Lucene

## Веб-интерфейсы

### Neo4j Browser

```
http://localhost:7474
```

Логин: `neo4j`
Пароль: указанный в `NEO4J_PASSWORD` (по умолчанию `password123`)

В Neo4j Browser можно:
- Визуализировать граф метаданных
- Выполнять Cypher-запросы
- Исследовать связи между объектами

### Интерфейс поиска

```
http://localhost:8006/search
```

Простой веб-интерфейс для поиска по метаданным без использования Cursor.

## Требования

- Docker Desktop с WSL2
- Лицензионный ключ
- Embedding модель (LM Studio или CPU)
- **Выгрузка конфигурации** из Конфигуратора
- ~2 ГБ RAM для Neo4j

## Порт

**8006** (MCP сервер)
**7474** (Neo4j Browser)
**7687** (Neo4j Bolt)

## Образ Docker

```
comol/1c_graph_metadata:latest
```
