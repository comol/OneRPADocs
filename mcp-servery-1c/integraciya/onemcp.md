# OneMCP: MCP-сервер внутри 1С

OneMCP — не Docker-сервис из набора поисковых серверов, а расширение конфигурации 1С, которое публикует инструменты непосредственно через HTTP-сервис платформы.

## Состав поставки

- расширение `OneMCP.cfe`;
- HTTP-сервис `APA_MCP` с `rootUrl="mcp"`;
- справочник `APA_Инструменты`, из которого динамически формируется `tools/list`;
- пример `ИнструментыДляРазработки.xml` с готовыми инструментами.

В исходниках расширения установлен префикс `APA_` и режим совместимости `Version8_3_17`. Это значение режима совместимости расширения, а не обещание поддержки любой версии платформы начиная с 8.3.17; требования поставки проверяйте в разделе [Конструктор MCP серверов для 1С](../../konstruktor-mcp-serverov-1c/README.md).

## Endpoint и протокол

При публикации базы с именем `mcptest` endpoint выглядит так:

```text
http://localhost/mcptest/hs/mcp
```

Текущая реализация — stateless JSON-RPC 2.0 поверх HTTP:

- `initialize`;
- `tools/list`;
- `tools/call`;
- пакетные запросы;
- уведомления без ответа — HTTP 204.

В `initialize` сервер объявляет `protocolVersion: "2025-03-26"`. Параметры инструментов публикуются по английскому алиасу `ИмяEn`; текущая схема описывает их как строки.

{% hint style="warning" %}
Это собственный JSON-RPC-over-HTTP слой 1С, а не FastMCP Streamable HTTP transport. Перед использованием с новым клиентом проверьте полный handshake: `initialize`, `notifications/initialized`, согласование версии, заголовки `Accept`/`Content-Type` и ожидания клиента по `Mcp-Session-Id`. Не объявляйте совместимость только по успешному `GET` endpoint-а.
{% endhint %}

## Готовые инструменты

Файл `ИнструментыДляРазработки.xml` содержит:

| Инструмент | Назначение |
|------------|------------|
| `vcexecutecode` | Выполнение произвольного кода 1С |
| `vcexecutequery` | Выполнение запроса 1С |
| `validatequery` | Проверка синтаксиса запроса |
| `vcloggetlasterror` | Получение последней ошибки журнала регистрации |

{% hint style="danger" %}
`vcexecutecode` и `vcexecutequery` дают ИИ возможность выполнять произвольный код и запросы с правами пользователя публикации 1С. Пример `default.vrd` сам по себе не добавляет аутентификацию, а пример Apache с `Allow from all` открывает сетевой доступ. Используйте отдельного пользователя 1С с минимальными правами, TLS/reverse proxy, аутентификацию, сетевой allowlist и не публикуйте endpoint в Интернет напрямую.
{% endhint %}
